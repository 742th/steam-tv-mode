# Адресное переключение телевизора при нескольких дисплеях

## Цель

В TV Mode показывать изображение только на телевизоре, даже если к ПК подключены два обычных монитора. В PC Mode возвращать конфигурацию экранов, которая была до запуска TV Mode. Один и тот же сценарий должен работать с одним монитором и ТВ, а также с двумя мониторами и ТВ.

## Текущее поведение

`tv-mode.ps1` проверяет через `WmiMonitorID`, что среди активных дисплеев есть имя, совпадающее с `$TvDisplayName` или Samsung, а затем вызывает `DisplaySwitch.exe /external`. Найденный дисплей не передаётся команде: она переключает глобальный режим и не выбирает конкретный экран. `pc-mode.ps1` аналогично вызывает глобальный `/internal`.

## Решение

Использовать MultiMonitorTool от NirSoft для команд адресного управления дисплеями и сохранения/загрузки конфигурации. Утилита остаётся внешней зависимостью, как уже используемый SoundVolumeView; её исполняемый файл не включается в репозиторий. README укажет официальный источник и настройку пути.

Официальная документация MultiMonitorTool: https://www.nirsoft.net/utils/multi_monitor_tool.html

## TV Mode

1. Найти активный телевизор по настроенному `$TvDisplayName` и сопоставить его с записью MultiMonitorTool. Использовать уникальный идентификатор монитора из этой записи для дальнейших команд.
2. Если совпадения нет или оно неоднозначно, вывести предупреждение и завершить TV Mode до изменения конфигурации экранов. Это исключает случайное отключение не того Samsung-дисплея.
3. Если резервной конфигурации ещё нет, сохранить текущую конфигурацию всех дисплеев в `%LOCALAPPDATA%\steam-tv-mode`. Не перезаписывать резерв при повторном запуске TV Mode: он должен описывать исходную конфигурацию ПК.
4. Включить телевизор, отключить остальные дисплеи и сделать телевизор основным. После этого продолжить существующее переключение звука, питания и запуск Steam Big Picture.

Если MultiMonitorTool отсутствует или не удаётся сохранить исходную конфигурацию, не менять схему экранов и не вызывать `/external`. Остальные настройки TV Mode можно применить только после успешного адресного перехода, чтобы не запускать игровой режим с неожиданным изображением.

## PC Mode

Если резервная конфигурация существует, загрузить её через MultiMonitorTool. Удалять резерв только после успешного восстановления; при ошибке оставить файл и вывести предупреждение, чтобы следующая попытка могла повторить восстановление. Это возвращает исходные один или два монитора независимо от количества экранов.

Если резервной конфигурации нет, сохранить существующий вызов `/internal` как запасной сценарий. Остальные текущие действия PC Mode — звук, план питания и выход из Big Picture — остаются без изменений.

## Настройка и границы

- Настроенное имя телевизора должно отличать его от других дисплеев; если несколько экранов совпадают по имени, пользователь указывает более уникальную часть имени.
- MultiMonitorTool устанавливается отдельно на каждом ПК. Путь к нему настраивается рядом с остальными параметрами скрипта.
- Предполагается расширенный рабочий стол. Документация MultiMonitorTool указывает, что утилита рассчитана на конфигурации с расширенными, а не дублирующими экранами.
- `hotkey-listener.ps1`, аудио-логика, имена аудиоустройств и планировщик задач не меняются.

## Проверка

На Windows проверить вручную:

1. Один монитор и ТВ: TV Mode оставляет включённым только ТВ; PC Mode возвращает монитор.
2. Два монитора и ТВ: TV Mode оставляет только ТВ; PC Mode возвращает оба монитора и их обычное расположение.
3. Неоднозначное имя ТВ: конфигурация экранов не меняется и выводится понятное предупреждение.
4. Повторный запуск TV Mode не перезаписывает резерв конфигурацией только с ТВ.
5. Ошибка восстановления PC Mode сохраняет резерв для повторной попытки.

Текущая среда — macOS и не может выполнить Windows PowerShell или MultiMonitorTool; окончательная проверка переключения требует Windows.
